# Kinlin AI - 数据使用说明

## 📊 数据存储方式

### 1. 数据库（PostgreSQL）✅ 必须

**用途**: 持久化存储核心业务数据

**存储内容**:
- 用户信息（User）
- 对话记录（Conversation, Message）
- 角色信息（Role）
- 用户反馈（UserFeedback）

**是否必须**: ✅ **是** - 系统核心功能依赖数据库

**配置位置**: `backend/src/main/resources/application.yml`

```yaml
datasource:
  url: jdbc:postgresql://localhost:5432/kinlin_ai
  username: root
  password: 367343
```

---

### 2. Redis缓存 ✅ 必须

**用途**: 缓存和会话存储

**存储内容**:
- 用户会话
- 对话上下文缓存
- 临时数据

**是否必须**: ✅ **是** - 提升性能，减少数据库压力

**配置位置**: `backend/src/main/resources/application.yml`

```yaml
redis:
  host: localhost
  port: 6379
```

---

### 3. 文件存储（JSON）⚠️ 部分必须

**用途**: RAG文档存储、知识图谱数据

**存储位置**: `data/rag/documents.json`

**是否必须**: 
- ⚠️ **RAG功能必须** - 如果使用RAG功能，需要文件存储
- ❌ **其他功能可选** - 不使用RAG时不需要

**自动创建**: 系统会自动创建 `data/rag` 目录

---

### 4. 内存缓存 ⚠️ 可选

**用途**: 数字人形象缓存、临时数据

**存储内容**:
- 数字人形象数据（`digital_human_service.avatar_cache`）
- 知识图谱数据（`knowledge_graph_service.kg`）

**是否必须**: ❌ **否** - 仅用于性能优化，重启后丢失

**特点**: 
- 速度快
- 重启后需要重新生成
- 不占用磁盘空间

---

## 📋 API必填字段说明

### 一、数字人API

#### 1. 创建数字人 `POST /ai/digital-human/create`

**必填字段**:
- ✅ `role_id` (str) - **必须** - 角色ID

**可选字段**:
- ❌ `personality` (str) - 可选，默认为空字符串
- ❌ `profession` (str) - 可选，默认为空字符串
- ❌ `style` (str) - 可选，默认 "realistic"

**示例**:
```json
// 最小请求（只填必填字段）
{
  "role_id": "lawyer_001"
}

// 完整请求
{
  "role_id": "lawyer_001",
  "personality": "严谨、专业",
  "profession": "律师",
  "style": "realistic"
}
```

#### 2. 更新动画 `POST /ai/digital-human/animation`

**必填字段**:
- ✅ `role_id` (str) - **必须** - 角色ID
- ✅ `audio` (bytes) - **必须** - 音频数据
- ✅ `text` (str) - **必须** - 文本内容

**注意**: 所有字段都是必填的

#### 3. 切换风格 `POST /ai/digital-human/style`

**必填字段**:
- ✅ `role_id` (str) - **必须** - 角色ID
- ✅ `new_style` (str) - **必须** - 新风格（realistic/cartoon/anime）

---

### 二、情感感知API

#### 1. 情感分析 `POST /ai/emotion/analyze`

**必填字段**: 
- ⚠️ **至少提供一个** - `text`、`audio_features`、`facial_features` 至少有一个

**可选字段**:
- ❌ `text` (str) - 可选
- ❌ `audio_features` (dict) - 可选
- ❌ `facial_features` (dict) - 可选

**说明**: 
- 如果都不提供，返回默认中性情感
- 提供多个会进行多模态融合

**示例**:
```json
// 只使用文本
{
  "text": "我最近很焦虑"
}

// 多模态
{
  "text": "我最近很焦虑",
  "audio_features": {"pitch": 0.6, "energy": 0.7},
  "facial_features": {"expression": "worried", "intensity": 0.8}
}
```

#### 2. 情感感知回复 `POST /ai/emotion/response`

**必填字段**:
- ✅ `question` (str) - **必须** - 用户问题
- ✅ `base_role` (dict) - **必须** - 基础角色配置

**可选字段**:
- ❌ `text` (str) - 可选，用于情感分析
- ❌ `audio_features` (dict) - 可选
- ❌ `facial_features` (dict) - 可选
- ❌ `user_emotion` (dict) - 可选，如果提供则跳过自动分析

**示例**:
```json
// 最小请求
{
  "question": "我最近很焦虑",
  "base_role": {
    "role_id": "counselor",
    "personality": "温和、耐心"
  }
}

// 完整请求
{
  "question": "我最近很焦虑",
  "base_role": {
    "role_id": "counselor",
    "personality": "温和、耐心",
    "knowledge_domain": ["心理", "情感"]
  },
  "text": "我最近很焦虑，工作压力很大",
  "audio_features": {"pitch": 0.6},
  "facial_features": {"expression": "worried"}
}
```

---

### 三、角色融合API

#### 1. 融合角色回答 `POST /ai/role-fusion/fuse`

**必填字段**:
- ✅ `question` (str) - **必须** - 用户问题
- ✅ `available_roles` (list) - **必须** - 可用角色列表
  - 每个角色必须包含: `role_id`, `knowledge_domain`
- ✅ `role_responses` (dict) - **必须** - 各角色的回答 {role_id: response}

**可选字段**:
- ❌ `personality` (str) - 可选，在角色信息中

**示例**:
```json
{
  "question": "我想创业，需要法律和商业建议",
  "available_roles": [
    {
      "role_id": "lawyer",
      "knowledge_domain": ["法律", "合同"]
      // personality 可选
    }
  ],
  "role_responses": {
    "lawyer": "从法律角度..."
  }
}
```

---

### 四、知识图谱API

#### 1. 构建知识图谱 `POST /ai/knowledge-graph/build`

**必填字段**:
- ✅ `documents` (list) - **必须** - 文档列表
  - 每个文档必须包含: `doc_id`, `text`

**可选字段**:
- ❌ `metadata` (dict) - 可选，文档元数据

**示例**:
```json
{
  "documents": [
    {
      "doc_id": "doc1",
      "text": "张三是一名律师..."
      // metadata 可选
    }
  ]
}
```

#### 2. 混合检索 `POST /ai/knowledge-graph/search`

**必填字段**:
- ✅ `question` (str) - **必须** - 查询问题
- ✅ `vector_db_results` (list) - **必须** - 向量数据库检索结果（可以为空列表）

**可选字段**:
- ❌ `top_k` (int) - 可选，默认 5

#### 3. 知识推理 `POST /ai/knowledge-graph/reason`

**必填字段**:
- ✅ `question` (str) - **必须** - 查询问题

## 🔍 数据依赖关系

### 功能依赖图

```
核心功能（必须）
├── PostgreSQL数据库 ✅ 必须
│   ├── 用户管理
│   ├── 对话记录
│   └── 角色管理
│
├── Redis缓存 ✅ 必须
│   ├── 会话管理
│   └── 性能优化
│
└── 文件存储 ⚠️ 条件必须
    └── RAG功能 → 需要文件存储
        └── 知识图谱 → 需要文件存储（或数据库）
```

### 功能可选性

| 功能 | 数据库 | Redis | 文件存储 | 内存缓存 |
|------|--------|-------|---------|---------|
| 基础对话 | ✅ 必须 | ✅ 必须 | ❌ 不需要 | ⚠️ 可选 |
| 数字人 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 | ⚠️ 可选 |
| 情感感知 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 |
| 角色融合 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 | ❌ 不需要 |
| RAG | ❌ 不需要 | ❌ 不需要 | ✅ 必须 | ⚠️ 可选 |
| 知识图谱 | ❌ 不需要 | ❌ 不需要 | ⚠️ 推荐 | ⚠️ 可选 |

## 💡 使用建议

### 最小化部署（不启用RAG）

**需要**:
- ✅ PostgreSQL数据库
- ✅ Redis缓存

**不需要**:
- ❌ 文件存储（RAG相关）
- ❌ 知识图谱功能

### 完整功能部署

**需要**:
- ✅ PostgreSQL数据库
- ✅ Redis缓存
- ✅ 文件存储（`data/rag` 目录）
- ⚠️ 内存充足（用于缓存）

---

## 📝 字段必填性总结

### 所有API的必填字段

| API | 必填字段 | 说明 |
|-----|---------|------|
| 创建数字人 | `role_id` | 其他字段都有默认值 |
| 更新动画 | `role_id`, `audio`, `text` | 全部必填 |
| 切换风格 | `role_id`, `new_style` | 全部必填 |
| 情感分析 | 至少一个输入 | text/audio/face至少一个 |
| 情感回复 | `question`, `base_role` | 其他可选 |
| 角色融合 | `question`, `available_roles`, `role_responses` | 全部必填 |
| 构建图谱 | `documents` | 必填 |
| 混合检索 | `question`, `vector_db_results` | 全部必填 |
| 知识推理 | `question` | 必填 |

---

## ⚠️ 注意事项

1. **数据库是核心**: 没有数据库，系统无法运行（用户、对话等功能）
2. **Redis推荐**: 虽然可以不用，但会严重影响性能
3. **文件存储**: 只有使用RAG功能时才需要
4. **内存缓存**: 完全可选，仅用于性能优化
