## 修复的问题

### 1. 类型不兼容错误

**错误信息**:
```
java: 不兼容的类型: io.micrometer.core.instrument.Counter无法转换为java.util.Optional<io.micrometer.core.instrument.Counter>
java: 不兼容的类型: io.micrometer.core.instrument.Timer无法转换为java.util.Optional<io.micrometer.core.instrument.Timer>
```

**错误位置**:
- `MetricsController.java` (3处)
- `MetricsService.java` (3处)

**问题原因**:
`meterRegistry.find().counter()` 和 `meterRegistry.find().timer()` 返回的是 `Counter` 和 `Timer` 类型，不是 `Optional<Counter>` 和 `Optional<Timer>`。当meter不存在时，这些方法可能返回 `null`，但类型仍然是 `Counter`/`Timer`，不是 `Optional`。

**修复方案**:
1. 将 `Optional<Counter>` 改为 `Counter`
2. 将 `Optional<Timer>` 改为 `Timer`
3. 使用 null 检查替代 `Optional.map()`
4. 移除不必要的 `Optional` 导入

**修复前**:
```java
Optional<Counter> apiRequestsCounter = meterRegistry.find("api.requests").counter();
double apiRequests = apiRequestsCounter.map(Counter::count).orElse(0.0);
```

**修复后**:
```java
Counter apiRequestsCounter = meterRegistry.find("api.requests").counter();
double apiRequests = apiRequestsCounter != null ? apiRequestsCounter.count() : 0.0;
```

## 2. 功能集成

### 2.1 MetricsService集成到ChatService

**目的**: 在发送消息时自动记录消息数指标

**修改文件**: `ChatService.java`

**修改内容**:
1. 添加 `MetricsService` 依赖注入
2. 在保存AI回复后调用 `metricsService.recordMessageCount()`
3. 添加异常处理，确保指标记录失败不影响主流程

**代码示例**:
```java
// 记录消息数指标
try {
    metricsService.recordMessageCount();
} catch (Exception e) {
    log.warn("记录消息指标失败: " + e.getMessage());
}
```
