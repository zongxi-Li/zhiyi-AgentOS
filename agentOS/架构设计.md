# AgentOS 架构设计

## 分层原则

AgentOS 的核心定位是运行时内核，不承载任何具体行业 Agent 的硬编码实现。

- `agentOS/`：核心运行时。只提供通用 Module、Interface、注册机制、调度机制、治理机制和基础 Adapter Interface。
- `agent/`：应用服务层。负责 FastAPI 入口、业务编排、兼容旧接口、加载启用哪些领域 Pack。
- `agent/packs/`：领域能力包。法律、教育、编程、写作等具体 Agent、Skill、Workflow、Prompt 和领域数据都放在这里。
- `knowledge/`：知识库服务。负责文档处理、向量存储、检索能力。
- `llm/`：LLM 网关服务。负责模型供应商适配、成本路由、性能路由和指标。
- `shared/`：跨服务共享类型、工具和常量。
- `infrastructure/`：基础设施配置。

核心规则：

1. `agentOS/src/agentos/core` 不允许直接 import 任何具体领域 Pack。
2. `agentOS/src/agentos/agents` 只保留通用 Agent Interface 和 Registry。
3. 具体领域 Agent 通过 Pack Manifest 和 Pack Registry 注入运行时。
4. 新增行业能力时，只新增 `agent/packs/<pack_id>/`，不修改 AgentOS Core。
5. Core 面向 Interface 编程，应用层负责选择 Adapter 和 Pack。
